# 快速主路线与低消耗交接

## 先锁定真正要回答的问题
从原题提取各问的对象、输出、硬约束、量纲和依赖，标识 Q1/Q2 等稳定编号。区分预测、解释、排序和决策：准确拟合不等于解释机制，相关性不等于干预效果，综合得分不自动等于最优决策。先查数据粒度、可用时点、缺失、单位和会改变答案的缺口；单位先保留原题标签，换单位时显式给出转换因子，避免翻译引入数量级变化。只读必要字段，不先进行宽泛检索。

## 用结构选路线
寻找守恒、单调、凸性、可分解性、支配关系、上下界和不可辨识性。先问“是否可行、能否由这些数据识别、结论是否依赖未知偏好”，再拟合或优化。选择一条主路线，说明最简单可信基线为什么不足，以及主路线如何修正；仅在关键不确定可能改变选择时比较一个有实质区别的备选，不列算法菜单。按需读取 `task-families.md` 对应小节。

## 让创新成为可检验机制
按“题目痛点 → 方法改变 → 预期作用 → 对照/证伪 → 失效条件”写创新。创新也可以是证明某假设不必要、给出决策边界或减少计算，不必增加模型层数。区分已有文献方法、针对本题的改造和真正待验证的新假设，不自称学术首创。若基线已足够，保留基线，把价值放在稳健决策、可靠验证和解释上，不强凑创新。

## 最小检查只为解除阻塞
交接包给出关键公式/算法、数据接口、基线、验收量和备用路线触发。先运行的检查应能决定保留还是放弃路线：解析极限、小枚举、量级/可行性界或小样本回测。不能改变选择的全量扫描、全文写作、精美绘图留给 Modex。无执行结果就标“待验证”，不能把预期增益写成事实。已执行探针也须核对代码是否真正遵守时间、约束和样本口径；输出标签、网格步长和聚合方式须与实际计算相符。失败数字不得交给 Modex 当有效证据。

## 交接到此收束
用 `assets/strategy-handoff.md` 生成一个能执行的包。优先保留决策理由和实现细节，同一事实不在多个章节反复展开；长计算附脚本和结果路径。每问至少说清输入→计算→输出→检查；明确哪些事实已核对、哪些检查已跑、哪些由 Modex 完成。Modex 返回论文、可执行代码、机器结果、图表来源及问题覆盖表，见 `modex-handoff.md` 与 `assets/modex-return.md`。交接后等待实际初稿；不为填表而先完整解题。豆包仅用于 Skill 制作测试，不进入正式比赛。

## 审查与额度
第一版读完整论文；后续按变更依赖检查受影响的公式、数字、图表、摘要和结论，优先修结果，再修英文。同一失败检查修复后重跑；已通过且输入未变的检查复用。检索只服务影响路线或结论的缺口，确定性工作用本地脚本，日志只返回指标和路径；完成交接或必要修订即停止扩展。

将核对事实写为短 `brief.md`，列出影响它的实际输入和结果依赖：

```bash
python3 scripts/context_cache.py snapshot --root CASE --file problem.pdf --facts brief.md --output CASE/context.json
python3 scripts/context_cache.py check --root CASE --manifest CASE/context.json --show-facts
```

`fresh` 仅表示列出文件未变。`stale` 时重读变化和受影响结论，再修订摘要和快照；新增依赖也须绑定。首次没有 results.json 就不列它。历史输出的 `fresh` 标签可能已过时，每次复用先重新运行 check。没有实际计量，不报告节省百分比。
