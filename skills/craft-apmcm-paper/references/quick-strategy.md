# APMCM 低 Codex 额度快速主路线

## 1. 先定主路线，不先堆方法
只依据题目原文、数据字段、量纲、采样间隔、各问输出和约束选择路线：有明确物理或业务机理时，先建机理、半机理模型；小样本或关系可解释时，先用统计、时间序列或简单方程；按数据、约束与机理选择统计、优化或仿真工具；复杂方法需用对照证明新增成本有价值，不能把尚未试算的增益当事实。复杂度本身不是入选理由，不得默认神经网络、启发式优化或三维仿真优先。

## 2. 一轮锁定一个可证伪假设
主路线必须写成一个可检验命题，例如“某机制能在不增加未观测量的前提下，使核心指标相对基线稳定改进”。先定义成功阈值、失败信号、对照数据和最小样本；假设被证伪即切换，不为保住复杂方法反复修补。

优先识别能减少计算的结构：守恒、不变性、单调性、凸性、上下界、对称与可分解性。能用证明或精确小枚举回答的问题，不用大规模仿真替代；创新也可以是消除一个看似必要的假设，而非增加模型层数。

## 3. 基线与最小试算
先规定最简单、可复现基线：常数、线性、经典公式、规则模型或同类常用模型。交接包写明最小试算方案、验收指标和失败触发条件；只有路线选择依赖试算时才先运行小样本检查，不默认完成全部计算和图表。已运行的试算只需回答量级、方向、异常值和关键假设是否成立；其余交给 Modex 实现并返回证据。所有公式保留单位、数据区间和适用条件。

## 4. 创新要落在机制
创新优先来自题目机制：约束修正、误差结构、分段分层、参数时变、不确定性传播、可解释替代、数据与机理融合。用证明、精确对照、基线、消融或灵敏度说明价值，说明新增假设为何有效、何时失效；禁止无实验证据承诺最高奖级。

## 5. 备用路线触发条件
出现以下任一情况才切换：核心假设未通过最小试算；残差含系统性结构且原模型无法解释；数据量、频率或边界条件不支持；关键指标无改进或稳定性恶化；计算成本阻断复现。切换优先选择同数据可复用、改动最小的方案。

## 6. 分工与 Modex 交接
正式比赛分两阶段：Skill 先生成 Modex 交接包并等待；Modex 完成解题实现、计算、图表和全文初稿；Skill 收到实际论文、代码和结果后审查并作必要修改。交接字段包括：题目各问、数据与字段、约束、推荐路线及理由、关键假设、基线、最小验证方案、公式单位、创新对照、备用路线触发、交付清单、未证实结论。已有试算与冻结结果及哈希按实际附上；未执行处写“待验证”，不把完整求解设为交接前提。

## 7. 额度控制
按需加载材料，增量复用代码和结果；已有结果不重算，脚本只回传摘要、指标和图表路径，不贴长日志。仅在关键不确定影响结论时检索；首次交接只做选择路线必需的检查；收到初稿后按关键结论的风险和证据缺口执行必要验证，不一律重做整题。确定性检查用本地脚本，输出精简摘要；复审聚焦变化及其影响。豆包仅用于制作和测试 Skill，不进入正式比赛流程。没有实际计量，不得写“节省 XX%”。

## 本地摘要缓存

将已核对事实写成短 `brief.md`，列出所有会影响它的输入与结果依赖。首次保存：

```bash
python3 scripts/context_cache.py snapshot --root CASE --file problem.pdf --file results.json --facts brief.md --output CASE/context.json
python3 scripts/context_cache.py check --root CASE --manifest CASE/context.json --show-facts
```

`fresh` 只说明列出的文件未变，可复用此前核对过的事实；`stale` 时只重读变更文件及受影响的结论。新增依赖也需更新快照。缓存不能取代事实核验，不能在输入变化后继续引用旧结论。初次只有题目时，不必虚构results.json；仅列实际存在的依赖。
