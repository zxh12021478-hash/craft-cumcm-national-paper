# 求解方案与结果复核

按需用于优化/调度或声称“最优”的初稿。优先利用凸性、可分解性、界或小规模精确枚举；只有问题结构和预算需要时才选启发式/多目标算法，不默认安装某求解库。

## 可行性与最优性分开

先核对原题→变量→约束的映射，尤其边界、跨期守恒、辅助变量、整数性及信息时序。再独立代入候选解重算。线性部分可使用不调用求解器的标准库工具：

```bash
python3 scripts/check_linear_solution.py --input candidate.json --output linear-audit.json
```

示例只是接口，不是赛题答案：

```json
{
  "model": {
    "sense": "max", "c": [3, 1], "bounds": [[0, 2], [0, 2]],
    "A_ub": [[1, 1]], "b_ub": [3], "integer_indices": [0, 1]
  },
  "candidate": {"x": [2, 1], "reported_objective": 7},
  "tolerances": {"absolute": 1e-7, "relative": 1e-9, "integer": 1e-7}
}
```

`A_ub x≤b_ub`、`A_eq x=b_eq`；无该类约束时可省略。每个变量显式给边界，`null` 表示该端无界，不暗加非负。目标按原题 min/max 的 `c·x+offset` 还原，不把求解器内部取负后的数直接交稿。`offset` 可省略为0。

工具逐项返回左右值、违例和容差，整数性仅用小于半个整数步长的绝对容差。将原始候选JSON和审计报告一并纳入现有哈希证据记录，系数/解/容差变化就重检，不复用旧PASS。`linear_feasible` 与报告目标值是否一致分别记录；即使可行也可能不是最优。PASS只对声明的线性部分有效，不能证明数据来源、单位、模型忠实度、非线性或未列出的约束。容差要按量纲和决策需求定，不能扩大容差掩盖违约。

保留求解状态、时限、最好可行值、有效界和差距的原始证据。限时得到的可行解不自动是最优；未找到可行解也不自动证明不可行。最优性需适用的界/对偶证据或完整枚举等支持；上述工具始终不签发最优性结论。

## 多目标和随机优化的有界实验

- 先筛可行点，再谈非支配集。最小违例候选仍可能不可行；归一化、修复后重新代入原始约束。
- 记录各目标方向、单位和缩放。权重未知时保留权衡，不把一个加权分数称为所有偏好下最优。
- 方法对照采用相同输入、可行域和目标评价次数，并同时记录用时；随机算法按预算比较多个种子，不能只挑最好一次。不强制统一迭代数，因为每次迭代的评价成本可能不同。
- 若用超体积等前沿指标，对照须共享固定参考点、目标方向和缩放，并说明参考依据；各自归一化后指标更大不能直接说明前沿更好。常数目标先记录并共同处理，避免除零或各算法删除不同目标后比较。
- 停止规则按实际预算和决策稳定性约定。保留当前最好可行版本；更多迭代、复杂算法或第二个AI的一致意见都不是最优性证据。
