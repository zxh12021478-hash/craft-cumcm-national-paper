# 推荐解题思路大纲

> 文档性质：AI 推荐的非约束性方向。写作 Agent 可基于题目、数据和自身分析采用、
> 修改、组合或否决本建议，并自主负责公式、算法、计算、代码、结果和完整初稿。

## 一、题目本质与核心矛盾

用简洁语言指出研究对象、最终决策、最难识别或最难优化的结构，以及为什么常规做法
可能不足。不得把“使用某算法”写成题目本质。

## 二、各小问的角色与依赖关系

| 小问 | 在整题中的作用 | 依赖的前序信息 | 推荐的概念方向 | 主要风险 |
|---|---|---|---|---|
| 问题一 | 根据实际题面填写 | 根据实际题面填写 | 根据实际题面填写 | 根据实际题面填写 |

说明哪些小问负责发现规律、估计参数、建立机制、预测状态或形成决策，以及前一问的
哪些输出会进入后一问。若小问相互独立，应明确说明，不得强行制造统一模型。

## 三、推荐的总体方向

给出一个明确但非强制的主方向，解释它为什么比透明基线更契合题目结构。模型名称
只能服务于机制说明，不得把多个流行算法并排列为所谓完整方案。

## 四、逐问推荐思路

按题面逐问说明：该问实际要回答什么、建议抓住什么结构、适合比较哪些模型族、最终
应形成什么类型的证据。保持概念级，不写完整公式、计算步骤、参数、伪代码或代码。

## 五、建议重点打磨的创新

- 主创新：具体基线缺陷 → 结构性改动 → 预期带来的可验证价值。
- 辅助创新一：仅在确有独立贡献时填写。
- 辅助创新二：仅在确有独立贡献时填写。

不得把换算法名称、模型堆叠、增加装饰性图表或事后统一灵敏度分析当作创新。

## 六、验证证据、主要风险与备用方向

说明需要用什么证据区分主方向和透明基线，哪些假设一旦失败会改变结论，以及一个
简短的备用方向。验证、灵敏度、鲁棒性、仿真或消融应由实际风险触发，不为补流程而做。

## 七、建议的论文叙事主线

说明完整初稿最值得突出的一条故事线：题目中的关键矛盾如何被结构化、核心模型如何
解决它、结果如何转化为直接答案，以及验证如何支撑这一答案。

## 八、给写作 Agent 的两段专项建议

> 以下两段必须根据本题题号、任务类型、附件结构、逐问目标和候选模型重新写成可直接
> 交给写作 Agent 的具体建议。不得原样复用模板句，不得出现未替换占位符，也不得把
> 任意图表、仿真、伪代码或页数配额冒充赛题要求。

### 1. 题型适配、模型主线与高价值可视化建议

先准确判断本题及各小问属于预测、解释、测量、分类、优化、控制、评价、网络空间或
复合任务中的哪一种，并用题面证据说明判断；随后以一段连贯、具有执行指向的文字，
告诉写作 Agent 应优先呈现什么机制、原理、几何关系、业务过程或信息流，以及这些图
分别帮助解释哪一问。对数据与结果图，应把图形选择映射到实际证据任务，例如分布与
异常、时间变化与变点、空间结构、相关和滞后、预测误差与不确定性、基线比较、可行域、
目标权衡、策略边界或状态演化；可以建议组合图、小多图、误差带、热力图、网络图或
三维曲面，但只能在数据维度和比较目的真正支持时使用。高级感来自准确编码、信息层次、
统一视觉语言和最终页面可读性，不来自固定图量、装饰性三维效果或刻意排斥简单图形。
本段要具体到本题的小问和变量关系，使写作 Agent 看完即可理解“画什么、解释什么、
用什么证据判断图是否有价值”。

### 2. 求解真实性、验证闭环与成文质量建议

以一段连贯而具体的文字要求写作 Agent 以真实题面、真实附件和可复现计算为唯一结果
来源，优先选择与实际机制和数据规模匹配的模型，并在完整初稿中解释关键推导、求解
逻辑和每问直接答案；比较模型时应明确透明基线、公平数据划分、统一评价指标和选择
理由，灵敏度、鲁棒性、消融、不确定性传播或独立验证应针对最可能破坏结论的因素。
若题目确有随时间演化、随机事件、迭代控制或空间运动，再建议真实仿真及关键帧、轨迹、
状态面或二维/三维互补展示；若没有，就明确不应为满足形式而制造仿真。所有图表必须
具有编号、单位、可读字体和正文解释，流程图必须对应实际实现；附录只保留复现核心
结果所需的主要代码与说明，篇幅服从当年官方规则而非固定页数。摘要应在结果生成后
围绕逐问方法、核心量化答案、验证和创新效果组织，信息密度服从真实性和首页版面，
不能先写结论、强行铺满页面或用加粗代替逻辑重点。本段还应明确禁止生成数据、虚构
结果、补写未核实文献和用复杂模型掩盖不确定性。

## 九、写作 Agent 的自由裁量声明

本大纲是推荐方向，不是技术合同。写作 Agent 应重新核对题目和数据，并可在证据支持
下改进、组合或替换模型及呈现方案；最终核心决策由参赛队员理解、审核和确认。
