# 历史数据的版本与表头冲突核对

本轮只处理2024 C全球宠物食品输入的一项实际缺口。已下载Alltech编写的[2024报告镜像](https://news.foodmap.vn/wp-content/uploads/2024/04/Alltech_Agrifood-outlook-report-pdf-2024.pdf)，核对相关完整页并目视检查第8、18页。20页原PDF仅留本地；公开[来源定位](../evaluations/apmcm/source-vintage/source.json)及[算术检查](../evaluations/apmcm/source-vintage/check.py)，不转载整份报告。

第8页行业汇总表的年份标题与第18页宠物明细表相反：按汇总表标题直读，2022为34.96、2023为34.70百万公吨，会得到下降约0.744%；该行却报告增加0.26。宠物明细表明确列2023为34.96、2022为34.70，与增加0.26及正文正增长相符。本轮采用明细表对应关系，同时保留两份原样转录和冲突记录；这是有依据的解释，不冒称出版方勘误。

表中报告增长0.74%，由已四舍五入的两个水平数计算约0.749%。不能把尾数差异直接判为数据错误：在各水平数舍入半宽0.005下，增长可在约0.720%至0.778%之间，包含报告值。汇总表标题直读则在相同舍入范围内始终为负，舍入不能解释方向冲突。结果见[检查记录](../evaluations/apmcm/source-vintage/check-results.json)。

由此取得一个历史生产增长区间的来源依据，补充2022生产量；旧演练已采用的2023锚点34.96保持不变。生产不等于消费，一个年度增长也不是未来增长模型或预测区间。原2024 C计算、英文稿、摘要和PDF均未改，不重复已通过的检查。

报告第2页还说明早期调查数据存在修订。因此在现有`forecast-information.md`中增加两个短段：观测年份与实际使用的数据发布版本分别绑定；历史回测不能使用预测时点之后的修订值。增长须比较可比版本，评估须说清针对首次发布还是修订结果。沿用已有时间检查器，示例展示错误申报发布滞后会通过、正确申报修订时点则拒绝；这只是声明元数据检查，不是真实回测，也不能自动发现伪填时点。报告元数据不证明当时可公开取得。

原始检索还暴露了后发2025/2026数值及2023报告索引。它们未进入计算；2023镜像本地握手超时，未宣称已下载、逐页核实或取得其哈希。没有据此构造跨版本增长序列。

本轮仅修改两个现有引用：预测信息核对和它的条件入口；未增加生产脚本或额外赛时参与方。新算术/舍入/时间元数据检查及技能结构检查通过，34份安装文件与源码一致。未运行付费Modex、豆包或独立AI接收测试；这是局部来源审查，不是模型行为提升的独立证明。国赛版与生产脚本未改，旧40项检查复用。

后续只有获得可比的多期消费、库存/损耗或市场份额/估值数据，才能继续解除经验校准缺口；本轮不重新宣布已知规则未知项，也不把这份行业报告当竞赛规则。
