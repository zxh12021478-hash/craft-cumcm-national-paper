# 交接接收测试：类别 ID 不能被列表顺序替代

这轮在已有原生豆包会话继续2024 D制作测试。接收方只实现最小起步接口：通用平方损失的QUBO转换和冻结线性模型的三分类投票，另报告实际待做项。没有训练、完整求解或付费Modex调用。它是已有反馈背景下的接收回归，不是隔离盲测，也不证明实际Modex兼容性。

## 抓到的实际失败

交接规定零分和多类同票均选较小类别ID，生成代码却把“较小”解释成类别列表中先出现。把`[0,1,2]`改成`[2,0,1]`，同一模型、同一输入就可能从0变成2。原自查在四个冻结点上得到1.0的合成准确率，没有暴露此错；该数字不是Iris性能证据。

根检查在新的60组小QUBO赋值通过后，于类别列表重排断言失败；再独立构造“所有两类分数为零”和“三类各得一票”两个反例，均复现0→2。原始失败代码和产物已冻结，[公开反例记录](../evaluations/apmcm/handoff-receiver/raw-failure.json)保留失败状态。

## 最小修复与实际复验

同一会话定向修复两个位置，分别取两类ID与获胜ID集合的最小值；没有重排每对类别，从而保留正负分方向。QUBO和SDK发现函数AST未变。修复版不是只写在建议里：完整代码经Codex读取后，实际换数据执行。

[可复算检查](../evaluations/apmcm/handoff-receiver/check.py)和[结果](../evaluations/apmcm/handoff-receiver/check-results.json)包括：

- 四个新矩形编码问题，共60组赋值，直接残差平方和与QUBO能量最大绝对差约1.42e-14。
- 72个不同“模型—样本”组合，在两个类别列表顺序下作144次参考比对；另检查分类器列表重排，以及反转一对类别并同时反转分数符号的等价表示。
- 第三个两类分类器能改变最终预测；预测接口及依赖没有评估标签入口。两个原始反例在修复版均返回正确的0。

公开前后实现仅提取三个纯函数，与真实接收代码AST等价；它们是评估材料，没有增加到比赛运行脚本。详细证据与限制见[评估](../evaluations/apmcm/handoff-receiver/assessment.json)。

## Skill 改动与剩余限制

只在分类引用补一段：平局规则绑定实际ID或明确优先级；顺序没有语义时，用一次重排反验，覆盖零分和多类平票。它不要求所有任务都采用“最小ID”，不新增表单或完整训练前置门槛。

接收方在其Python3.12.14环境报告未发现Kaiwu；Codex审查了发现方法但未重复运行或安装，不能据此断言其他环境也没有。实际指定SDK求解、AR预测、Iris训练/指标、深度特征头均未完成。这一轮补齐的是最小接收实现的实际运行与修错证据，未完成2024 D整题。国赛核心、上一轮已通过的长稿摘要/PDF和未变化的40项生产测试未重复处理；本届规则未知项也未据此解除。
