# 不调用付费 Modex 的 APMCM Skill 开发优化

按当前预算约束，本轮没有调用 Modex。豆包仅在制作阶段做产出、独立接收与摘要读者试用；正式比赛仍是 Skill 出思路交接、Modex 实现写初稿、Skill 审查修改。替代测试不冒充真实 Modex 兼容性验证。

## 已落实的四项改进

1. **交接可执行性**：强调接收者无需原聊天，明确时序、单位、边界、状态与输出；共享参数/结果写一次，复杂证据放附件；可选扩展不提升为原题要求。已用另起的豆包任务独立实现一个新微型题并重跑核对。
2. **摘要重点验证**：只给读者摘要与输出要求，检查能否恢复每问答案、机制、比较、单位与边界；再由主代理对完整正文/结果核真。只交正式摘要文本，审查说明另存。读者理解不是真实性验证。
3. **路线止损**：试算先明确要决定什么、预算、成功/失败动作；缺数据、验证失败、计算超时和真正不可行分别处理。备用方案须自行通过必要检查，不把放松问题或未验证方案当有效回退。
4. **增量复查**：复用现有哈希缓存，可选依赖图追踪数据/代码→结果→图表/摘要，并保留未解决事项；口头澄清也能使旧事实失效。简单编辑不用强制建立依赖图。

## 验证与实际限度

- **交接接收者**独立实现两日供水模型，主代理重跑与解析界一致：最低成本2.9 CNY；压力情景缺额0.055 m³、不可行。只验证这一原创微型模型。
- **摘要读者**未收到正文/结果表，恢复了三问的直接答案与口径；主代理核对事实一致。根版本进一步压缩重复限制，未再次做独立读者测试。
- **脚本检查**：40项APMCM测试通过，其中10项新测增量传播、澄清失效、未解决项及异常输入。技能结构校验通过。

试用仍发现交接重复、可选扩展变必答、部分自报审计范围过强等问题，原输出和根修订分别保留。[完整开发验收](../evaluations/apmcm/low-cost-development/assessment.md)说明哪些已实际测试、哪些修订未再次独立测试。

原国赛核心未改，没有新增依赖。真实 Modex 往返继续未验证，不作为当前继续优化的前提。没有准确 Codex 用量/账单记录，因此不声称节省了多少额度或费用，也不估算获奖概率。
