# 摘要优先：先选证据，再写英文 Summary

目标是让读者迅速恢复每问答案、起作用的机制、相对价值及可信边界。不要以短为唯一目标，也不要把完整事实表压成一篇小论文。本协议不规定本届词数、段数或页面格式。

## 先核真，后选择

交接阶段只规划每问需要的答案与证据，不预填结果或承诺式摘要，不增加交接前完整求解。Modex 初稿返回后，先读完整原题、正文、附录及实际结果/代码，修正影响结论的错误，再冻结可用事实。只收到摘要时不能宣称已做全文一致性审查。

沿用原题 Q 编号、问题覆盖表和 headline ledger，不另建平行结果体系。在已有记录中区分“核真需要保留”和“摘要需要说出”：事实核对通过，不等于必须进入摘要。

新增结果、验证或派生数字先进入修订正文及结果记录，才能用于摘要；仅在报告建议“以后补正文”不算完成。若只获准改摘要，删去正文未报告的新内容并另报建议。日差额、服务人数、单位换算等若只是在重复已报主指标，不必加算来增加数字密度。

## 写作前完成一次内容选择

从已核事实选出下面的内容，再起草；不要沿着原摘要/正文段落逐段缩写。简单题用内部短条目，复杂题可在已有 ledger 加“摘要/正文保留”及理由，不默认另交长计划。

| 摘要作用 | 选择什么 |
|---|---|
| 直接回答原题 | 每问的决策、关键结果及必要单位；同问多个必答量仍须覆盖。不可行证书、不可辨识性和条件答案也可直接回答，不强造数字 |
| 解释为什么有效 | 真正起作用的建模机制或针对本题的改变；不列软件、预处理或算法菜单 |
| 说明相对价值/可信度 | 最能支持或推翻推荐的比较、证明或验证；对象、分母、范围和方向明确。保留不同问的必要比较，不机械地全篇只留一个数字 |
| 防止误读 | 会改变解释的失败条件、适用域或验证缺口；贴近主张，用一次共享限定承载 |

通常只留正文：原始输入参数清单、整张候选/可行解表、落选方案逐项说明、推导步骤、同一收益的多种等价计数、软件流程，以及逐条“未声称显著/概率/最优”等审查说明。若这些本身是原题必答输出或理解机制的必要信息，则保留相应部分，不套禁词规则。

例如已经给出最优方案、成本和证明方式，就不因“数据正确”再抄所有候选的容量、成本和排名。错误曾经出现过，也不必在正式摘要复述原错误数字；修复后的有效结论与仍影响推荐的失败才需要说。

**证据结论不等于完整证书。** “完整枚举得到唯一最优”可以在摘要说明证明方式与结论；四个可行方案的逐项成本并不因此成为摘要必答。下列取舍尤其容易混淆：

| 任务 | 摘要中的证据结论 | 留在正文的证明/明细 |
|---|---|---|
| 完整候选集求解 | 覆盖范围、最优方案/值、唯一性及必要对照 | 所有输入系数、可行方案逐项清单、逐项排除证明 |
| 按硬约束切换方案 | 可行性先于成本、所选方案、导致推荐变化的关键条件 | 每个落选方案的分数/违约值；不因要证明“仅此可行”就全抄 |
| 参数识别与换算 | 哪个实验识别什么、所需参数及任务单位、决策结果 | 多组等价参数、重复单位值、逐步推导和原始观测列表 |

起草前在现有 note/ledger 留一份短选材记录：**必答结果、机制、决定性证据、必要边界、正文保留**。前四项构成写作内容，最后一项不再搬入摘要。该记录不需要新脚本、外部 agent 或额外模型调用。

## 从选择结果组织，而非从旧摘要删句

用紧凑链组织真实依赖：`具体难点/目标 → 起作用的机制 → 各问直接答案 → 决定性证据与建议`。相关问题可共享一句机制或限定，不把任务清单、逐问结果和结尾推荐重复三遍。已有基线足够时，贡献可以是更可靠的边界、验证或解释，不强凑学术首创。

下例仅示范取舍，不能把这些事实带入当前题。假定正文已完整报告：三个模块的全部参数、八种子集、四个可行方案；Q1 最优 A+B 成本12，定义的参考 B+C 成本15；Q2 在 A/B 分别失效后保留3/4，要求至少3；全部为给定加和模型。摘要保留答案、完整枚举和参考差异，输入清单与其余可行解留正文：

> We enumerate all eight module subsets to minimize installation cost under normal and single-module-failure supply requirements. The unique optimum is A+B at CNY 12, 20% below the defined reference B+C at CNY 15. If A fails, supply remains 3 units/day; if B fails, it remains 4, both meeting the required 3. The result is exact for the stated additive-capacity model and contingency set; physical performance remains unvalidated.

示例的长度和句式不是通用配额；更复杂的必答输出可能需要更多篇幅。文献/方法贡献需要解释时保留解释，不能为了仿写例句而删掉它。

## 起草后做语义删除检查

逐句问：删掉这句或其中一组数字后，读者是否仍能恢复所有必答结论、机制、决定推荐的证据和必要边界？若能且不损失必要解释，实际删除或合并，不只改同义词。尤其检查：

- 输入清单/全表是否只是从正文搬来；结尾是否重说已有推荐。
- 同一个比较是否同时报总量、逐日差额、人数、比例和全部子组，却没有增加决策信息。
- 限定是否承担具体作用，还是复述审查过程及未要求的未来实验。

新增一句时先判断它应替换或合并哪个低价值内容；只有确实补足必答或重要证据才扩写。删除后再核对覆盖表，防止把约束违反、条件推荐、单位或一个必答问一起删掉。若删减破坏答案，恢复必要信息，不能凭字数达标宣布通过。

若摘要仍逐项列出非必答的整组输入、全部可行方案或全部淘汰原因，**本次删除检查未通过**：回写一版实际去掉这些明细的摘要，再查答案与机制是否齐全。不能只在 note 写“已删全表”，却在摘要逐行复述其主要列。原题确实要求完整清单/证明时，记录其要求并保留所需内容；不为模仿短例子删掉必答。

## 数字、英文和正文一起核对

- 比较带对象、场景、方向与单位；相对下降 `(baseline-candidate)/baseline` 需基线非零且可比。百分比/百分点、总量/均值、最坏/平均、各折均值/合并指标不能互换；必要计算放可复算结果中。
- 保留证据范围：候选最好≠全局最优，场景占比≠实际概率，拟合≠样本外验证，数值收敛≠实测验证，代理指标≠实测节能。单位核原始源，不只核正文重复标签。
- 区间带对象和依据；不把情景范围叫置信区间，不补造显著性、误差条或奖项概率。模型/参数变化后重核受影响的摘要、正文、结论和图表。
- 英文的主语、比较参照、否定、时态、情态与因果强度和证据一致。不得把 may 变 does、associated 变 causes；每个公式/数字/单位/定性判断对齐正文与机器结果。图内文字需视觉检查。

[2021 官方历史规则](https://www.apmcm.org/detail/2416)对摘要方法与重要结论的重视支持本协议，不提供本届词数、评分权重或获奖概率。案例按 `exemplar-decisions.md` 选择性学习，不模仿冗长输入清单、整表搬运或案例错误。

## 交付与停止

优先交一版正式英文 Summary。文件只含可替换正文和必要标题；审查范围、来源映射、删留理由、未验证项与待办另放简短说明，复用既有记录。不默认多版本、逐句评分或双语全文。

初稿必须完整读过；后续只复查变更及依赖，不重复全审未变材料。正文证据齐、答案覆盖、比较正确且必要边界保留后结束本次重构。最终“可提交”还须按本届已确认模板实际渲染与检查；未知规则、未执行实验或单纯字数下降不能变成通过。
