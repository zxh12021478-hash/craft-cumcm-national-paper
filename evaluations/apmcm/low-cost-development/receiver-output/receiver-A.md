## 1. 从交接包读出的模型口径（答案相关）

| 项 | 读出的口径 |
|---|---|
| 模型 | 两日、按日总量连续 LP；变量 q1,q2,S1,S2；不建日内调度；容量仅约束日末 S1,S2 |
| 单位 | 水量/库容 m³；价格 p1=1、p2=3 CNY/m³；成本 CNY |
| 平衡 | S1 = S0+I1+q1−D1 = 1+q1；S2 = 0.9·S1+I2+q2−D2 = 0.9·S1+q2−3 |
| 损耗顺序 | 第 1 日之前不计损耗；**仅 S1 跨日到第 2 日损失 10%**（日 2 期初=0.9·S1）；日 1 当日用水不扣损；S2 为终端，无损耗/无储水价值 |
| 约束 | q1,q2≥0 连续；0≤S1,S2≤4；整数、溢流、负库存、缺水变量、日内约束一律禁止；无随机性 |
| 场景 1（Q1） | q1max=q2max=2 |
| 场景 2（Q2） | 仅 q1max 改为 0.05，q2max 仍为 2，其余不动；不得加缺水变量凑可行 |
| 停止约定 | Q1 求最优并代入复核；Q2 若不可行则交不可行证书（上界、缺额、恢复阈值），不硬造可行解 |
| 回退约定 | 无求解器时用标准库二维顶点枚举替代 LP，仍输出完整求解状态；若 Q1 报不可行先查平衡符号/损耗口径；偏离路线须说明理由 |

## 3. 机器结果（独立运行，Python 3.14.7，仅标准库）

运行命令：`python3 solve-A.py`（stdout 同时落盘 `run-A.log`，JSON 落盘 `results-A.json`）。M1 与 M2 结果精确一致，断言通过，M3 全部检查 True。

### Q1 原场景（q1 上限 2）— 最优，成本 2.9 CNY

| 量 | 值（m³） | 精确分数 |
|---|---|---|
| q1（第 1 日购水） | **2.000**（用满上限） | 2 |
| q2（第 2 日购水） | **0.300** | 3/10 |
| S1（第 1 日日末） | 3.000 | 3 |
| S2（第 2 日日末） | 0 | 0 |
| 最优成本 | **2.9 CNY** | 29/10 |

可行域为三角形，仅 3 个顶点（q1,q2）：(1/9, 2) 成本 55/9≈6.111；**(2, 0.3) 成本 2.9（最优）**；(2, 2) 成本 8.0。
机制：日 1 水跨日打九折后等效 1/0.9≈1.11 CNY/m³（日 2 可用口径），远低于日 2 的 3 CNY/m³，故 q1 用满；起作用的约束是 q1≤2 与 S2≥0（q2=0.3），库容上界 4 不起作用（S1 仅达 3）。
可行性检查方法（已执行）：求解状态=optimal；候选解代回 S1=1+q1、S2=0.9·S1+q2−3 两式恒等成立；q1,q2≥0、q2≤2、0≤S1,S2≤4 全部满足；目标值 q1+3q2=2.9 复算一致。
另核：不跨日蓄水的就近基线 q1=0 → S1=1 → 日 2 需 q2=2.1>2，**基线在原场景即不可行**，说明必须跨日规划。

### Q2 压力场景（q1 上限 0.05）— 不可行（infeasible）

两种方法均得可行域为空。精确不可行证书：
- q1 用满 0.05 时 S1,max=1.05（=21/20）；
- 日 2 最大可供水量 = 0.9×1.05+2 = **2.945 m³（589/200）< D2=3**；
- 缺额 = **0.055 m³（11/200）**；
- 恢复可行阈值：q2 需达 **2.055 m³（411/200，现上限 2）**；或保持 q2 上限 2 时 q1max 需达 **1/9≈0.1111 m³（现为 0.05）**。
未引入任何缺水变量或其他变量凑解。
