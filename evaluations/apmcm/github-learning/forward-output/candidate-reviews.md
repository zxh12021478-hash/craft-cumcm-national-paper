# 线性候选审查：linear-candidates.json（A/B/C）

> 复核对象：`forward-input/linear-candidates.json` 三份候选（同一模型，不同候选解）。
> 三层结论严格分开：**① 约束检查（可行性）→ ② 目标值口径（c·x 与报告值）→ ③ 最优性（独立证据）**。
> 工具：Skill `scripts/check_linear_solution.py`（只做声明线性约束/边界/整数性/目标的独立代入重算，**始终不签发最优性**，也不验证模型忠实度、单位、非线性或未声明约束）。
> 最优性证据：本包独立完整枚举 `checks/candidate_enumerate.py`（25 个整数格点，仅对声明的有界整数模型有效）。

## 0. 声明模型（三份相同，原文照录）

- max 5x1 + 4x2
- 0 ≤ x1 ≤ 4，0 ≤ x2 ≤ 4，x1,x2 整数
- 2x1 + x2 ≤ 8；x1 + 2x2 ≤ 8
- 枚举结果（已执行）：25 个格点中 17 个可行；**声明模型最优目标值 23，唯一最优点 (3,2)**。

## 2. 逐候选审查

### 候选 A：(3,3)，reported_objective=27，status=optimal
- **① 约束检查**：FAIL。`A_ub[0]` 左端 2·3+3=9 > 8，违例 1；`A_ub[1]` 左端 3+2·3=9 > 8，违例 1（容差约 1.09e-7）。边界 0≤3≤4、整数性均通过。`linear_feasible=false`。
- **② 目标值口径**：按声明 sense=max、c=(5,4) 重算 c·x+0=15+12=**27**，与报告值 27 一致——算术本身自洽，但这是"不可行点上的目标值"，不具备决策意义。
- **③ 最优性**：枚举确认 (3,3) 不在 17 个可行点中；"optimal" 状态无效。
- 处置：拒绝；需回到建模/求解环节定位为何输出违反两条约束的点。

### 候选 B：(2,2)，reported_objective=18，status=optimal
- **① 约束检查**：PASS。两约束左端 6、6 均 ≤8；边界、整数性通过。`linear_feasible=true`。
- **② 目标值口径**：重算 10+8=**18**，与报告值一致。
- **③ 最优性**：**工具未证明也无法证明最优**（`optimality_verified=false`）；独立枚举给出最优 23@(3,2)，B 目标差距 5，status=optimal 为虚假最优。可行≠最优。
- 处置：可作为可行解保留，不得作为最优解交稿；需给出更优解或界/对偶证据。

### 候选 C：(3,2)，reported_objective=−23，status=optimal
- **① 约束检查**：PASS。左端 8、7 均 ≤8；边界、整数性通过。`linear_feasible=true`。
- **② 目标值口径**：FAIL。max 问题按 c·x 重算为 15+8=**+23**，报告为 **−23**，违例 46；形态符合"把求解器内部最小化取负后的数直接交稿"（solver-review 明确禁止该口径）。
- **③ 最优性**：独立枚举确认 (3,2) 是声明模型唯一最优点，正确目标值 +23；但**当前提交记录因目标值口径错误不能直接采纳**。
- 处置：修正 reported_objective 为 23（保留 x=(3,2)）后记录方与最优性证据一致；枚举仅覆盖声明模型，不担保模型本身与原题一致。
